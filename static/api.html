DEVELOPER GUIDE / V1

Any agent.
One approval boundary.

Create an API key in Connected agents. Use the key only on your server or in a local agent process.

Submit an action

POST /v1/actions
Authorization: Bearer YOUR_AGENT_KEY
Content-Type: application/json

{
  "title": "Save the reviewed report",
  "reason": "Report is ready for owner review",
  "tool": "save_file",
  "arguments": {
    "filename": "report.md",
    "content": "# Report\n\nYour content here."
  },
  "idempotency_key": "your-stable-request-id",
  "expires_in": 3600
}

Use a stable, unique idempotency key (8–100 characters) for each logical action. Identical retries return the original action; changed requests with the same key return 409.

Wait for a decision

GET /v1/actions/ACTION_ID
Authorization: Bearer YOUR_AGENT_KEY

Poll every few seconds. A key can only read its own agent's actions. The response includes status, approved arguments and the execution result.

Tool contracts

01

save_file

Arguments: filename and content. Only .md, .txt, .csv and .json. Max 50,000 characters. Always requires owner approval.

02

send_webhook

Arguments: payload (JSON object). The owner configures the public HTTPS destination in the dashboard. Always requires owner approval. No redirect following or automatic retry.

03

log_event

Arguments: message (1–2,000 characters). Records internal metadata immediately; no external tool action.

Lifecycle

pending → approved → running → succeeded
        ↘ rejected
        ↘ expired
        ↘ blocked
                       ↘ unknown

Unknown means an effect may have occurred. Check the destination before creating another request. Revocation stops unclaimed work; it cannot recall an in-flight action.

Do not let your agent execute the write independently after approval. Relay's worker executes it. API keys cannot approve actions.
